# 外部插件协议 v2

宿主只接受 `protocol_version = 2`。自带插件、示例和 SDK 同步使用 v2，不保留 v1 或旧双文本面板适配。

插件以独立进程运行。宿主不加载 DLL，也不携带 Python/Node 运行时。
安装位置默认是 `<数据目录>\plugins\<目录>\plugin.json`，数据目录默认是安装目录的 `data`，关闭便携模式后是 `%APPDATA%\MiniLauncher`；可用 `[plugins].directories` 指定其他目录。
安装或修改清单后从托盘重新加载。`>plugins` 打开图形设置管理器的插件管理页，显示启用/停用配置、清单错误及关键词冲突；该页不代表宿主实时运行状态。

GUI 插件页支持点击“安装目录”或“安装 ZIP”安装本地插件，将包含程序的插件包复制到配置文件同级的 `plugins/<id>`；安装器复用宿主清单校验，拒绝覆盖、同 ID/配置标识冲突及越界路径。可执行程序必须位于包内，外部解释器等布局可继续用“登记外部目录”登记原始目录。安装器不运行插件。

在插件卡片上点击“卸载”。卸载先保存停用配置，等待程序文件释放；默认安装目录中的插件会完整移动到同级 `plugin-backups`，保留数据及 `.mini-launcher-settings-*.toml` 配置快照，再清理活动配置。共享配置标识需先修正清单冲突。外部登记目录仅停用与取消直接登记，不移动源文件，并保留停用配置防止父目录再次发现后启用。安装/卸载须先保存其他草稿，均需确认。

插件可以在主配置的 `[plugins.<config_key>]` 下保存设置。宿主解析通用的 `enabled`、`keywords`、可选的布尔字段 `direct_display` 和整数 `priority`，其余字段作为不透明配置保留，由插件自行读取和校验。宿主在 initialize 中传入可选 `settings_path` 和 `config_key`，指定主配置的绝对路径及配置段名称。

清单可声明 `config_key`（默认将 id 中的 `-` 替换为 `_`）和 `config_defaults`（插件目录内的相对 TOML 文件路径）。默认配置文件使用平铺字段，例如 `enabled = true`、`keywords = ["demo"]` 及插件自己的选项；宿主根据清单自动补齐缺失字段，保留已有值和注释。`mini-launcher.exe --register-plugin <插件目录>` 可登记任意插件并添加自定义搜索目录。宿主不负责插件专属的旧配置迁移。

WorkspaceHub 集成与翻译插件在独立的 `MiniLauncher.plugs` 项目中维护、构建和分发，不随本项目构建或预装。第三方插件使用相同的清单、配置 schema 与 JSON-RPC 2.0 协议，通过 GUI 安装插件 ZIP 或目录即可使用。

## 查询展示

查询开始只更新宿主的等待状态，不用空列表或“正在查询插件”面板替换结果。同一范围与独占插件路由内继续输入时保留已有结果，收到实际响应后更新；实际空响应仍会清空结果。切换范围、独占插件路由或图片输入模式时清除上一上下文的内容。

查询持续超过 300ms 后，宿主在输入框下沿显示不表示百分比的流动细进度条，不改变布局或推迟结果。连续输入保持等待计时与动画连续，相关来源查询完成或关闭窗口后结束。插件无需为此修改协议；插件主动返回的富文本加载内容仍照常展示。

保留结果中的声明式动作使用条目自带的内容。插件执行与数据读取回调需要由当前查询结果继续提供该动作 ID；等待新结果期间，过期回调会提示稍后重试，避免调用已失效的插件内部动作。

## GUI 设置描述（可选）

在插件目录中放置 `settings.schema.json`，无需修改 `plugin.json` 或协议版本。GUI 读取 `fields` 下与主配置专属字段同名的描述，用于字段标题、说明、枚举选择及保存前基础校验；未知字段继续支持按 TOML 类型编辑。嵌套表直接展开，字符串数组每行一项。GUI 不启动插件来生成表单，插件仍负责完整的业务校验。

```json
{
  "fields": {
    "maximum_results": {
      "title": "结果上限",
      "description": "最多返回 1–100 项。",
      "type": "integer",
      "minimum": 1,
      "maximum": 100
    },
    "default_editor": {
      "title": "默认编辑器",
      "type": "string",
      "enum": ["Zed", "VS Code"]
    },
    "hub_path": { "type": "path", "absolute": true }
  }
}
```

当前字段描述针对插件配置段的直接子字段。支持 `string`、`path`、`integer`、`boolean`、`array`；数值范围为整数，可选 `absolute` 要求绝对路径。GUI 为字符串枚举提供下拉选择，其他类型的枚举仍执行保存校验。没有描述文件时不增加插件专属校验；已停用插件的专属配置不做描述校验。发行脚本会随插件打包该文件。

字段可声明 `"visible_when": {"mode": "remote"}`：仅在同一配置表中的 `mode` 当前值等于 `"remote"` 时显示。多个条件须全部满足，使用严格 JSON 值比较，缺少依赖字段时隐藏；不声明或使用空对象时始终显示。条件随编辑立即更新，隐藏不会删除配置或重建编辑器，因此切换选项后仍保留各自的输入。条件只控制显示，不改变保存校验规则。此能力适用于所有插件，设置程序无需识别插件 ID 或业务字段。

字符串字段可声明 `"format": "hotkey"`，在手动填写文本框旁提供“按键录入”按钮。点击后按下组合键即可自动填入标准快捷键字符串，单独按 Esc 或转移焦点取消录入；Ctrl、Alt、Shift、Win 可组合使用。另提供双击 Ctrl、Alt、Shift、Win 按钮，其他同键双击可直接填写 `A+A`、`Space+Space`、`F1+F1` 等。插件全局快捷键接受含修饰键的组合键或同键双击，留空仍禁用。双击不拦截原按键行为，也无法检测其他软件占用；两次须按同一侧修饰键，按下间隔最多 350ms，每次按住最多 250ms，中途其他键或鼠标按钮会取消识别。

### Windows 凭据

`settings.schema.json` 可用 `"windows_credential": {"target_field": "credential_reference"}` 声明一组 Windows 普通凭据。插件默认配置应提供同名的字符串字段，值为该插件所用的凭据名称。设置页将该字段显示为独立的用户名和密码输入框，点击「保存凭据」后直接写入当前 Windows 用户的凭据管理器。密码输入框始终以空值打开。凭据内容由插件按名称读取，主配置仅保存凭据名称。旧版设置程序会将该字段显示为普通文本框。

可在 `windows_credential` 中加上 `"test": {"fields": ["endpoint"]}`，提供「测试连接」按钮。设置程序以 `--settings-test` 启动插件清单中的可执行文件，并通过标准输入发送一行 UTF-8 JSON-RPC 2.0 `settings.test` 请求。参数为 `settings`（指定字段的当前值）、`credential_target`、`username` 和 `password`。密码留空时，插件可按名称读取已保存的凭据。插件只读检查连接，在标准输出返回一行带相同 ID 和 `result.message` 的响应，然后退出。结果仅包含状态说明。

## 清单

```json
{
  "id": "mini-echo",
  "name": "Echo 示例插件",
  "protocol_version": 2,
  "executable": "echo-plugin.exe",
  "args": [],
  "keywords": ["echo"],
  "priority": 0,
  "timeout_ms": 800,
  "idle_timeout_secs": 30
}
```

`id` 使用英文字母、数字、`-`、`_`，最多 64 字符。`executable` 是插件目录内路径或绝对路径，工作目录为插件目录，`args` 不经 Shell 拼接。
关键词不区分 ASCII 大小写、不能包含空白，也不能与 `g`、`bing`、`e` 或 `>` 内置命令重复。自定义 Everything 关键词优先于插件。
`*` 是全局查询关键词，可与显式关键词同时声明，例如 `"keywords": ["path", "p", "*"]`。普通非空查询会将**完整原始输入**传入声明 `*` 且满足触发规则的插件，不移除第一个词；插件应对不适用的输入返回 `{"items":[]}`。全局结果按优先级与应用及 Everything 全局结果合并，再按宿主既有规则去重，保留各插件内部顺序。默认优先级相同时仍按应用、Everything、插件排列。

显式插件关键词优先，仅查询对应插件并独占结果，传入关键词之后的内容。空输入、`>` 命令、`设置`、显式网页及 Everything 查询不触发全局插件。`*` 本身不再作为字面触发词处理。

清单可声明 `"direct_display": true`（默认 false），让插件在综合范围空输入时直接显示结果，无需关键词，也不需要 `*`。用户可在 `[plugins.<config_key>]` 用 `direct_display = true/false` 覆盖清单默认值；此开关在插件设置 GUI 中显示，插件可在默认配置中提供。唤出窗口、清空输入和重载配置都会发起新查询。多个开启直接显示的插件按优先级合并，同优先级保持发现顺序，空输入只显示这些插件；其他搜索范围不触发它们。输入文字后恢复正常路由。请求为 `query = ""`、`is_global = false`，不执行全局输入防抖，查询本身不可执行复制等动作。停用、失效或关键词冲突的插件不参与直接显示。

清单可声明整数 `priority`（默认 `0`，范围 -2147483648 至 2147483647），数值越大，插件的查询启动顺序和结果合并顺序越靠前；同优先级保持发现顺序。此规则适用于全局查询及空输入直接显示，保留各插件内部条目顺序。并发查询仍在各插件完成时更新结果，不等待高优先级插件返回；优先级不改变触发条件、显式关键词路由、关键词冲突校验或独占规则，应用和 Everything 的优先级分别由根配置 `application_priority` 与 `[everything].priority` 控制，均默认 `0`，可在设置程序的“应用搜索”和“文件搜索”页调整。插件与它们使用相同的整数尺度，数值越大越靠前；同分保持应用、Everything、插件的原顺序。合并先排序后去重，重复条目保留优先级较高的版本。可在设置程序的插件列表卡片直接编辑优先级，沿用自动保存；主配置 `[plugins.<config_key>]` 中的 `priority` 覆盖清单默认值，不修改插件包。未设置覆盖时使用清单值。修改清单后需重新加载。

多个插件可共享 `*`，其他同名关键词或 id 冲突的清单不加载；最多加载 32 个清单。命中全局插件的输入等待 60ms，在此期间继续输入会替换旧请求并重新计时；显式关键词查询不等待。全局插件在 `[plugins].max_processes` 上限内独立查询（空闲进程也计入上限，必要时先回收），完成一个就更新结果；最终排列按上述优先级规则合并。上限为 1 时依次查询。每个插件沿用自身超时，失败不会中断其余插件，过期查询会取消正在运行的请求并停止后续调用，旧结果不会显示。进程复用及空闲回收保持生效。网页兜底等待全部查询结束后决定是否显示。当前不提供权限沙箱、下载商店或 Flow 兼容层。

### 全局触发规则

可在清单中声明 `global_trigger`，仅约束 `*`，显式关键词不受影响。规则在宿主内执行字符串判断，不访问文件系统，不启动插件；省略时等同 `{"type":"always"}`，兼容已有全局插件。

```json
"global_trigger": { "type": "path" }
```

`path` 匹配盘符、斜杠开头的路径、`~` / `~/`、`./` / `../`、`%变量名%` 和 `file://`；支持反斜杠及引号包裹。它只判断输入形态，不检查路径是否存在。仅有文件名的相对路径通过显式关键词输入，例如 `path report.txt`。

也可按任一前缀触发（忽略输入开头空白及大小写）：

```json
"global_trigger": { "type": "prefix", "values": ["https://", "ssh:"] }
```

`prefix` 需要 1–32 个非空字符串，每个最多 128 字节，不含控制字符；未知类型或无效规则会使清单加载失败。

## 传输与生命周期

stdin/stdout 上使用 UTF-8 NDJSON，每行一条 JSON-RPC 2.0 消息。stdout 只发协议；stderr 为插件日志，目前宿主丢弃 stderr。
每行最多 256 KiB、一次查询最多 100 项。JSON 错误、管道失败、超时或协议错误会停止对应插件，下次触发可重新启动。
普通查询默认超时 800 ms，可设为 50–5000 ms；首次 initialize 至少允许 1000 ms。
空闲退出可设 1–300 秒，默认 30 秒。宿主最多同时保留 `[plugins].max_processes` 个进程，超过时回收最久未使用的进程。

需要持续监听系统事件的插件可在清单中声明 `"resident": true`（默认 false）。启用后随宿主启动并初始化，进程不参与空闲回收或按需进程数量限制；查询和执行复用该进程，仍遵循协议、并发查询数量、取消和超时限制。最多额外常驻已发现的 32 个插件进程。禁用、配置重载和宿主退出会回收整个进程树；重载为仍启用的插件重新初始化。初始化失败显示在 `>plugins` 状态中；异常退出后可重新加载恢复，后续查询失败会回收会话，再次查询可重新启动。旧版宿主不识别此字段，需要更新宿主。
进程被加入 Windows Job，回收和宿主退出会结束整个进程树；这提供故障隔离，不限制插件本身的文件、网络或系统权限。

## 初始化

请求：

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocol_version":2,"host":"MiniLauncher","max_frame_bytes":262144}}
```

响应必须协商协议版本：

```json
{"jsonrpc":"2.0","id":1,"result":{"protocol_version":2}}
```

## 查询

输入 `echo hello` 时，关键词之后的内容作为 `query`：

```json
{"jsonrpc":"2.0","id":2,"method":"query","params":{"query":"hello","max_results":100,"generation":42}}
```

```json
{"jsonrpc":"2.0","id":2,"result":{"items":[{"title":"复制 hello","subtitle":"Enter 复制","action":{"type":"copy","text":"hello"}},{"title":"执行插件动作","action":{"type":"execute","id":"about"}}]}}
```

每项必须有 `title` 和 `action`，可选 `subtitle`、`icon`。`icon` 是相对于插件目录或绝对的图标路径；`.ico` 文件直接加载其图像，其他路径（例如可执行文件或快捷方式）使用 Shell 图标。宿主在后台按需加载。

query 参数额外包含 `is_global`：全局触发时为 `true`，显式关键词触发时为 `false`。插件可据此对普通输入中的未完成路径返回空结果，同时在显式查询中提供错误原因。

### 图片输入附件（可选）

清单声明 `"accepts_images": true` 后，插件可接收输入框通过 Ctrl+V、Shift+Insert 或标准 WM_PASTE 粘贴的图片。宿主将 PNG、CF_DIBV5／CF_DIB 转为独立 PNG 临时文件，输入框显示可选中删除的图片标记；完整标记删除后不再发送该附件，撤销／重做可恢复。一次输入最多 8 张，每张沿用 40 MiB 像素与单边 16384 的限制。显式关键词及插件范围沿用现有路由，宿主不自动选择某个特定插件。

查询新增通用 `attachments` 数组（无附件时为空），`query` 包含文字并移除完整图片标记：

```json
{"query":"图片说明","attachments":[{"type":"image","path":"C:\\Temp\\input.png","width":640,"height":480}],"max_results":100,"generation":42,"is_global":false}
```

路径为绝对路径，图片字节不进入 JSON 帧。临时文件由输入框及在途查询共同持有，输入清空或宿主正常退出后释放；插件若需要在之后的 execute 中保存，须在 query 中读取并暂存自己的快照，不依赖当前系统剪贴板或临时路径继续存在。查询仍不应执行持久化收藏、复制或粘贴。未声明 `accepts_images` 的插件收到图片查询时，宿主报告不支持图片输入，不调用其 query；已有纯文字查询行为保持兼容。宿主及设置程序仅识别通用能力和协议字段，无需了解插件业务。

### 结果项

标题最多 1024 字节、说明最多 4096 字节。查询应只生成结果，不执行所选动作。

结果项可选 `"paste_after_execute": true`（默认 false），仅支持 `copy` 或 `execute` 动作。选择后宿主先隐藏窗口；直接 `copy` 写入成功，或 `execute` 成功返回 `copy` / 空响应后，宿主恢复唤出前记录的窗口与输入焦点并发送一次 Ctrl+V。返回空响应的插件需先自行完成图片等内容的复制。回调错误不会触发粘贴，声明自动粘贴的回调不能返回 `open` / `launch`。上下文动作不继承此标记，可用于提供“仅复制”。原窗口关闭、焦点转移、用户重新唤出或操作按键未释放时取消粘贴，保留已复制内容。

结果项可选 `"action_label": "保存"`，供 `execute` 回调声明回车的动作名称（1–16 字、不能包含控制字符）。宿主在底栏和项目菜单中显示该名称；省略时显示“执行”。`open`、`launch`、`copy` 和自动粘贴仍根据实际动作显示“打开”“运行”“复制”“粘贴”，无需插件重复声明。

结果项可选 `"drag_id": "稳定标识"`，最多 256 字节、不含 NUL。超过系统左键拖动阈值后，或用户选择文本条目的右键“搜索”时，宿主单独调用只读 `prepare_drag`，参数为 `{"action_id":"稳定标识"}`；不调用 `execute`、不修改剪贴板、不触发 `paste_after_execute`。插件仅返回所选条目的完整拖动数据，不执行动作：

```json
{"jsonrpc":"2.0","id":3,"method":"prepare_drag","params":{"action_id":"stable-id"}}
{"jsonrpc":"2.0","id":3,"result":{"data":{"type":"text","text":"完整文本，保留换行"}}}
```

`data` 支持 `text`（`text` 最多 65536 字节、不含 NUL）、`image`（`path`）或 `files`（`paths` 数组，1–64 个路径）。路径相对于插件目录或使用绝对路径，单个路径最多 32768 字节。图片使用标准图片文件，由 WIC 解码，沿用图片尺寸及像素上限；图像本体不进入 JSON 消息。宿主在后台准备 Unicode 文本、PNG 及 CF_HDROP 文件格式，DIBV5 位图延迟到目标程序实际请求时生成；PNG 原文件直接复用字节，主线程进入 Windows OLE 拖动循环，只允许复制；准备完成前松开鼠标会取消。普通 `copy` 动作、绝对路径 `open` 动作及 HTTP/HTTPS 地址无须 `drag_id`，宿主可直接提供其文本或文件数据。省略 `drag_id` 的其他插件回调不支持拖出。

结果项可选 `"adaptive_height": true`，允许标题保留换行并按宽度换行；宿主根据内容在 60–160 逻辑像素范围内调整行高（文字最多使用 112），并按屏幕与结果区高度进一步限制。省略时沿用标准行高。`max_results` 仍限制返回条数，宿主窗口设置限制结果区总高度，变高条目可能减少同时可见的条数。

结果项可声明通用文本面板。协议 v2 不接受旧的 `original`、`translated`、`vertical` 等双栏字段：

```json
{"id":"translation","title":"中英互译","action":{"type":"copy","text":"译文"},"text_panel":{"layout":"auto","blocks":[{"id":"source","title":"原文","text":"Original text","selectable":true},{"id":"translation","title":"译文","text":"译文","selectable":true}]}}
```

`blocks` 包含 1–4 个区块，每块必须有稳定的 `id`、显示标题 `title` 和正文 `text`。区块 ID 在面板内唯一，最多 64 字节；标题非空，最多 128 字节，二者不含控制字符。正文最多 65536 个 UTF-8 字节，不含 NUL；完整响应仍须满足 256 KiB 帧限制。`selectable` 默认 true，使用只读原生文本组件；false 使用静态文字展示。空正文保留真实空值并显示“暂无内容”占位，不会把占位文字复制到剪贴板。

`layout` 为 `auto`（默认）、`horizontal` 或 `vertical`。auto/horizontal 在宽窗口中最多使用两列，窄窗口自动单列；vertical 始终单列。两块内容长度差异较大时为长内容分配更多宽度。测量、绘制和事件命中共用同一套几何计算。文档面板按区块的最小可读高度扩展结果区，普通结果数设置为 1 也不会裁掉区块；屏幕空间不足时整体布局按工作区缩放。

面板可提供 `state`（ready/loading/empty/error，默认 ready）、`message`（最多 4096 字节）和 `retry`（默认 false）。loading/empty/error 可以省略 blocks；也可以保留原有文本区，在状态行说明错误。`retry = true` 显示“重试”，点击或 Ctrl+R 重新发起当前查询，不执行条目的默认动作。loading 状态不允许默认执行，错误/空状态的默认执行也只会按声明重试。专用插件搜索范围等待、无结果及 RPC 错误时由宿主自动生成对应状态面板，不增加空闲轮询。

```json
{"id":"lookup","title":"查询未完成","action":{"type":"copy","text":""},"text_panel":{"state":"error","message":"网络请求失败，请稍后重试","retry":true,"blocks":[{"id":"input","title":"查询内容","text":"hello"}]}}
```

结果的可选 `id` 最多 128 字节，同一次响应内唯一；宿主按插件命名空间区分。它应保持稳定，不要使用内容或列表位置作为 ID。区块的 ID 在结果更新、重新排列及同一查询重试中也应保持稳定。宿主复用未变化的控件，保留选区和滚动位置；追加内容时保留仍有效的选区，已被替换的选中文字会清除，避免复制错误内容。查询文字或范围改变时清理旧面板。

搜索框中的 Tab 进入当前结果的第一个可选文本区，Shift+Tab 进入最后一个；正文 Tab/Shift+Tab 按区块顺序移动，越过边界返回搜索框。没有文本区的普通结果沿用 Tab 选择结果。正文 Esc 或 Ctrl+F 返回搜索框；直接输入文字或粘贴会切回搜索框继续输入。Ctrl+A 全选当前正文，Ctrl+C 或右键复制选区；正文 Enter 不执行条目，搜索框 Enter 执行默认动作。

正文拖选、内部滚动和状态重试拥有独立命中区域；区块标题可聚焦正文，只有面板总标题区域可拖出整个 item。面板无固定全文复制按钮。主题、字体、DPI、选区及焦点由宿主管理，选区操作不发送 JSON-RPC。选择期间只暂存每个来源最新的结果快照。正文滚动范围来自 DirectWrite 文档高度与视口高度，避免按固定行高猜测；文字、选区、细滚动条和右键菜单由宿主绘制并通过 DirectComposition 呈现。

结果列表和自绘菜单提供 UI Automation 的名称、角色、边界、选择和 Invoke 动作。原生文本区沿用系统文本可访问性并设置区块标题，正文内容和状态也通过结果说明暴露。自动化动作按稳定 ID 返回窗口线程处理，过期结果动作会被拒绝。

图片预览使用可选的 `preview` 对象，并自动启用自适应行高：

```json
{"title":"2026-11-07 00:20","preview":{"path":"thumbnail.png","original_path":"original.png","width":1920,"height":1080},"action":{"type":"execute","id":"copy:image-id"}}
```

路径相对于插件目录或使用绝对路径，最多 32768 字节；宽高必须为 1–16384 的整数，描述原图比例。图片行高为 84 逻辑像素，左侧图标（优先使用条目的 `icon`，未提供或加载失败时显示内置图片符号）、中间标题与尺寸（可附带 subtitle）、右侧 116×60 逻辑像素范围内等比例小缩略图。宿主后台按需加载本地图片，解码像素最多 40 MiB，缩略图不超过 800×240，缓存最多 16 项，未加载队列最多 8 项；失败显示占位。请使用内容对应的独立文件名，避免覆盖仍被缓存的路径。

可选 `original_path` 指向原图，沿用相同路径限制与标准图片文件格式。空输入或用方向键选中图片后，空格在屏幕工作区内打开大图预览，打开大图预览时才后台读取 `original_path`（省略时使用 `path`），与拖拽复用正在使用的原图；缓存不持有全局强引用，最后一个使用者结束后释放原图、缩放图和 PNG 字节。关闭预览会通知后台任务跳过后续缩放及回传；缩小使用 WIC 高质量重采样，能容纳的原图按实际像素显示，不放大。空格 / Esc 关闭预览，Enter 沿用原条目动作；编辑文字及输入法组合时保留空格输入。预览不修改剪贴板、不调用插件执行回调，也不导出明文文件；插件应在 `execute` 中完成所选图片的复制。

宿主使用系统 WIC 解码 PNG/BMP 等标准图片文件。元数据与路径通过协议传递，图片字节不进入 256 KiB 消息帧。

每项还可提供可选的 `context_actions`，在宿主右键菜单中追加操作；省略时保持原有行为，协议版本为 2：

```json
{"title":"结果","action":{"type":"copy","text":"默认内容"},"context_actions":[{"title":"查看详情","action":{"type":"execute","id":"details:123"}},{"title":"复制链接","action":{"type":"copy","text":"https://example.com"}}]}
```

每项最多 16 个菜单动作；菜单标题为非空文字，最多 128 字节，不得包含控制字符。动作沿用下表的类型、字段和长度限制，`execute` 使用所属插件的执行回调。打开或取消菜单不会执行动作；只有选中菜单项才执行。菜单动作可设置 `"confirm": true`，宿主先显示“确认操作 / 取消”菜单并默认选中取消，确认后才调用该动作。宿主不会向插件结果附加应用置顶、移除或管理员运行操作；即使插件返回 `open` 或应用图标也仍按插件处理。

支持的动作：

| type | 字段 | 行为 |
|---|---|---|
| `copy` | `text` | 宿主复制文字，最多 65536 字节 |
| `open` | `target` | 用默认程序打开路径/URL，最多 32768 字节 |
| `launch` | `executable`, `args` | 宿主启动绝对路径程序，`args` 为最多 64 项的字符串数组，不经过 Shell 拼接；程序路径最多 32768 字节，不得包含 NUL，含转义参数的命令行保守限制为 32767 个 UTF-16 单元 |
| `execute` | `id` | 宿主调用插件的 execute 方法，id 最多 256 字节 |

## 执行回调

```json
{"jsonrpc":"2.0","id":3,"method":"execute","params":{"action_id":"about"}}
```

插件可以自行完成动作，返回空对象，也可以返回宿主动作：

```json
{"jsonrpc":"2.0","id":3,"result":{"action":{"type":"copy","text":"插件执行结果"}}}
```

执行响应可返回 `copy`、`open` 或 `launch`，不能递归返回 `execute`。动作 id 应足以确定原始结果，避免依赖已被后续查询覆盖的临时状态。

带参数启动程序示例：`{"type":"launch","executable":"D:\\Tools\\ExampleEditor.exe","args":["--ports","server"]}`。宿主使用结构化参数启动，程序不属于插件的 Job，不会随插件空闲退出或宿主回收插件而结束。可用于编辑器或管理器等需要长期运行的应用。`launch` 是 v2 的宿主动作，插件应配合支持该动作的宿主版本使用。

## 取消与错误

查询过期时宿主发送尽力取消的通知：

```json
{"jsonrpc":"2.0","method":"cancel","params":{"id":2}}
```

插件无需响应通知；应尽快停止旧查询。宿主丢弃旧 generation/id 的响应；取消后仍未结束的任务会在原请求期限到达时回收进程。
RPC 错误使用标准 `error` 对象，例如 `{"jsonrpc":"2.0","id":2,"error":{"code":-32000,"message":"查询失败"}}`。

完整示例为 `examples/echo-plugin.rs`，构建和安装脚本为 `scripts/install-example-plugin.ps1`。

文本面板能力演示见 [文本面板 Demo](text-panel-demo.md)，源码为 `examples/text-panel-demo.rs`。运行 `scripts/install-text-panel-demo.ps1 -PackageOnly` 可生成可独立安装的插件目录和 ZIP；输入 `textdemo` 查看布局、选择复制、长文滚动、状态重试与内容更新等场景。

宿主通过环境变量 `MINILAUNCHER_DATA_DIR` 向插件提供当前数据目录。插件应将自身数据保存在该目录的独立子目录中，以跟随便携模式；请勿硬编码 AppData。用户显式指定的外部数据路径保持不变。
